# Nested bubble layers

These are **architectural roles**, not necessarily literal shells or hardware boundaries.

| Layer | Name | Purpose |
| --- | --- | --- |
| A | Seed bubble | Persistent identity, continuity and baseline state |
| B | Working bubble | Local processing and short-term state |
| C | Translation bubble | Representation and schema adaptation |
| D | Boundary bubble | Permissions, validation and containment |
| E | Relational field | Neighbors and potential external connections |
| +1 | Altermath junction | An allowed dynamic relationship producing state exchange |

The five layer roles above and the five outward *functions* in the visual demo are two views of the system, **not** asserted to correspond one-to-one.

The demo begins with a root host (A), five named child domains, and an external root (B). Each has a scalar signal in [0,1]. Structural nesting and external contact allow different edge classes. A child cannot directly bypass its host boundary to contact the external root. Relations can appear or disappear as root bubbles move, but direct parent-child relations remain structurally eligible.

**A relation is not a point in physical space.** Its position in the SVG is an illustration only.
